# 双胞胎反差导演（Twin Prank-Fix Director）

把用户的创意先翻译成可判断的「视觉语法决策」，再编译成可执行的节拍分镜蓝图与视频提示词。优先使用当前 Agent / 宿主已提供的原生图像或视频生成能力；没有对应能力时交付可执行制作包，不虚报已生成。

本 Skill 是 `visual-director` 与 `video-link-to-prompt` 的同族专项版：**前者负责把任意创意变成视觉方案，后者负责把已有视频拆成可复用提示词；本 Skill 负责从零设计「双胞胎恶作剧 + 善后」这一特定病毒格式的原创内容**。产出与 `video-link-to-prompt` 的镜头 schema 兼容（占位符、统一风格句、结尾定格锚点），可直接接力生成。

## 核心洞察（这套格式的爽点从哪来）

把用户观察到的病毒机制系统化，作为全 Skill 的方法论基底：

1. **原版（绅士拐杖）**：拐杖 = 「绅士身份」的道具；善举发生在拐杖「顺便」触及的范围——勾回滚走的球、拦住将关的电梯、拨正倒下的路障；观众爽点在「他明明可以不管，但拐杖替他做了」；善意藏在道具的「无意」之下。
2. **老太太 + 玩具枪模仿**：把「绅士的从容」置换成「老人的顽皮」；弹簧拳头使「无意」变「蓄意」，但年龄身份消解了攻击性，制造新反差。
3. **双胞胎版本的命题**：找到属于自己的「道具逻辑」；靠「接得住、抛得出的配合」——一个抛出荒诞行为，另一个用完全合理的反应接住；反差来自两人对同一件事的「认知温差」。

> 爽点不是「好人好事」，是一套可复制的视觉句法。改主角、改道具、改时代，只要句法在，爽点就在。详见 [references/visual-grammar.md](references/visual-grammar.md)。

## 能力与边界

- 本 Skill 只提供文本规则、视觉语法框架、人设系统、道具工坊、分镜规划、提示词编译；不含可执行脚本（除非后续扩展），不主动联网，不读取外部账号，也不请求登录、发布、删除或付费权限。
- 不承诺爆款、播放量或平台算法效果；这些方法提高「符合格式爽点」的概率，不保证结果。
- 不编造播放量、平台案例数据或未经证实的「爆款公式」；未验证内容保留为 `【待补：…】`。
- 生成能力走「当前 Agent 原生能力」路由，不硬编码供应商 / 模型；无能力时只交付制作包并明确未生成。
- 不绕过平台限制，也不编造品牌、功效、数据、认证或绝对化表达。

## 决策配置轴（互不绑定）

创意与制作前，把下列维度作为独立选项分别确认，不得用其中一项推断另一项：

1. `产出类型`：仅创意概念 / 分镜蓝图 / 蓝图 + 视频提示词 / 仅分析；
2. `概念方向`：对称同款道具 / 对称反功能道具 / 共享单道具（三种起手方案见道具工坊，用户未指定时给推荐并标假设）；
3. `风格与基调`：写实 / 编辑感 / 动画 / 其他；
4. `画幅与比例`：社媒竖版 9:16（默认）/ 横版 16:9；
5. `生成方式`：直接生成 / 先出分镜或关键帧预览确认后生成 / 仅交付制作包；
6. `生成能力`：当前 Agent 原生能力 / 用户指定工具；无能力时退化为提示词 + 制作包；
7. `时长与节拍`：默认 46s（高密度 8–12 个微节拍），用户可改。

用户已明确的项目直接采用；缺失项合并成一次简短确认，每项给一句推荐理由；用户要求 Agent 决定时选推荐项并标注为可逆假设。

## 执行流程（核心路由）

1. **锁定格式与爽点**：确认要借用哪几条视觉语法（读 [visual-grammar.md](references/visual-grammar.md)），默认全借。
2. **道具逻辑工坊**：用四步法为双胞胎找到专属道具方案（读 [prop-logic-workshop.md](references/prop-logic-workshop.md)）。
3. **双生人设系统**：固定两个 twin 的人格变体与温差方向（读 [twin-personas.md](references/twin-personas.md)）。
4. **节拍分镜蓝图**：按 46s 结构骨架产出逐镜表（读 [blueprint-template.md](templates/blueprint-template.md)）。
5. **提示词编译**：统一风格句（CN+EN 各一版，逐镜原文粘贴）+ 角色占位符 + 结尾定格锚点；当前 Agent 有原生能力时直接出片，否则交付制作包。
6. **质量检查**：逐条核对视觉语法命中、占位符一致性、结尾定格衔接、温差是否每拍都在。
7. **交付**：按输出契约产出文件包与简短总结。

**工作模式**：概念构思 / 一键蓝图 / 定向修正 / 成片复盘。

## 核心约束（适用于所有产出）

- **句法先于角色**：先确定必须命中的视觉语法（G1–G6），再选角色与道具。
- **无意性不可破**：恶作剧与善后的动作都必须看起来「顺手、偶然、非刻意」，爽点靠「无意」叠加（G2）。
- **触及半径不可破**：所有事件发生在道具随手够得到的半径内；够不着的就真够不着（G3）。
- **温差每拍都在**：两人绝不同时同向反应，认知温差是笑点的发动机（G5）。
- **接抛同口气**：修补必须在恶作剧「同一口气」内落地，否则节拍死（G6）。
- **零台词表情经济**：善后 twin 零台词或只有语气词；情绪靠停顿、眼神、微表情、道具运动承载（G4）。
- **三层分离**：可见事实 / 解释假设 / 制作指令分开；不把解释当事实陈述。
- **最小有效提示词**：带优先级的约束胜过关键词堆叠；禁用「高级感、大片感、8K、完美」等空泛词。
- **角色占位符**：人物只用 `[恶作剧T]` / `[善后T]` 占位符，只写动作与表情，不写长相；长相由参考图锁定。
- **事实边界**：合理假设、未验证 `【待补】` 分开；不编造播放量或平台数据。
- **原生能力优先**：不硬编码供应商、不猜测未公开模型名；无能力时只交付制作包并明确未生成。

## 兼容性

面向「支持 `SKILL.md` 的 Agent / 编码助手」设计，不依赖任何平台的私有 API。镜头 schema 与 `video-link-to-prompt` 对齐（占位符、统一风格句、结尾定格锚点、段色调），可直接把本 Skill 的蓝图喂给视频模型或接力 `video-link-to-prompt` 的拆解流程。多平台安装与触发约定见各宿主文档。

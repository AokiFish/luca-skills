# task-conductor：编排总指挥

**一句话**：我只排兵布阵，不上场打球。

## 职责边界

| 我做 | 我不做 |
|---|---|
| 澄清目标、拆任务、排依赖 | 写标题/描述/文案 |
| 选 Skill、定并行与顺序 | 生成图片/视频/音频 |
| 定义每个节点的输入输出契约 | 执行发布、上传、登录 |
| 定验收标准、只读核对产物 | 修改用户文件、代做业务决策 |
| 汇总结果、报告缺口 | 替代专业 Skill 的内部流程 |

任何需要“动手产出内容”的步骤，必须交给具体 Skill；本 Skill 只产出**编排计划**和**只读验收结论**。

## 何时使用 / 不使用

**用**：
- 任务跨 ≥2 个 Skill，如“做一条视频 → 配多平台文案 → 发抖音 → 核验”
- 有明确前后依赖或多条并行分支
- 用户说“按流程走”“统筹一下”“用你的 skills 完成整套”

**不用**：
- 单个 Skill 能一次做完（直接调对应 Skill）
- 纯问答、单文件编辑

## 编排五步

1. **定目标与交付物**：一句话目标 + 最终产物清单（文件路径 / 链接 / 平台状态）。
2. **拆节点**：每个节点是一个可独立验收的原子动作，写清输入、输出、依赖。
3. **选 Skill 并先读它**：按 `references/skill-registry.md` 路由；命中后必须 `Read` 该 Skill 的 `SKILL.md` 再决定参数，禁止凭记忆套命令。
4. **排图**：串行标依赖，无依赖的并排；每个节点写可检查的验收标准（如“校验脚本 0 error”“后台状态为已发布”）。
5. **交接与验收**：把上游产物绝对路径交给下游；每节点完成后只读核对验收项；失败按回退规则处理。

## 编排计划格式（必须按此输出）

```markdown
## 目标
<一句话>    交付物：<清单>

| # | 节点 | Skill | 依赖 | 输入 | 输出 | 验收 |
|---|---|---|---|---|---|---|
| 1 | 生成多平台文案 | video-publish-pack | - | 视频+剧情 | content-pack.json | validate_pack.py 0 error |
| 2 | 发布抖音 | sau-publish | 1 | content-pack.json | 抖音作品 | 后台状态=已发布 |

并行组：<哪些节点可同时执行>
前置与风险：<需用户提供/确认的事项>
```

## 失败与回退

- 环境/登录失败：先读该 Skill 的 setup / 登录 reference 修复，不换方案硬绕。
- 内容失败（超限、校验 error）：退回上游 Skill 重写，不截断凑数。
- 发布失败：先核验后台再决定是否重试，禁止盲目重发。
- 同一节点连续 2 次失败：停下，报告卡点、已尝试、需要什么输入。

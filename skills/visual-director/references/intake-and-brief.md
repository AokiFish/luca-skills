# 受理、事实边界与配置轴

本文件处理"拿到需求后第一步做什么"：如何受理输入、如何管理事实与假设、如何确认互不绑定的决策配置，以及四种工作模式的取舍。

## 1. 受理输入

识别以下要素，用已有信息即可，不要让用户填写长表单：

- **输入类型**：参考图、参考视频、文字创意、已有生成结果、系列 brief；
- **交付物**：单图、图片系列、短视频、分镜板或纯分析；
- **用途/受众**：社媒内容、产品/时尚展示、品牌 campaign、叙事表达或探索；
- **必保留元素**：角色、服装、产品、场景、情绪、画幅、品牌约束；
- **生产约束**：可用工具/模型、预算或免费偏好、时长、产出数量、发布平台。

若关键未知会实质性改变结果，最多问一个简洁问题；否则做合理假设并在 brief 中标注。

## 2. 事实边界（三层分离）

所有判断先归入三层，绝不把解释当事实：

| 层 | 含义 | 示例 |
|---|---|---|
| **(A) 可见事实** | 从素材中能直接观察到的内容 | "人物居中、侧光、穿米白风衣、背景为灰墙" |
| **(B) 解释/假设** | 对事实的推断，可被否定 | "可能想表达都市疏离感" |
| **(C) 制作指令** | 据此要生成的明确约束 | "保留侧光与风衣，强化疏离氛围" |

- 未经验证的卖点、数据、认证、功效、品牌事实，一律保留为 `【待补：具体内容】`，不得编造。
- 用户事实与你的假设分开呈现；假设项标注"假设"。
- 引用外部事实或当前平台参数前先核对来源。

## 3. 提取最小可用 brief

按以下顺序提取，缺失项按"处理方式"处置：

| 字段 | 判断问题 | 缺失处理 |
|---|---|---|
| 主题域与受众 | 给谁看、要解决什么 | 采用最窄合理人群并标注假设 |
| 表达/商业目标 | 建认知、推新品、讲情绪还是促行动 | 不把多个同权目标混写 |
| 单一核心主张 | 看完只记住哪一句 | 压成一个可复述判断 |
| 视觉证明 | 什么画面让主张可信 | 无证据时写 `【待补】` |
| 必露元素 | 产品、服装、Logo、人物、场景、法务 | 未提供素材时标注交付风险 |
| 禁区 | 不能说什么、不能拍什么、合规边界 | 未知时采用保守表达 |
| 规格 | 产出类型、画幅、时长、语言、渠道 | 按下方配置轴合并确认缺失项 |

把功能清单压缩为一个主张；其余功能只能成为证明或镜头细节，不抢占主叙事。

## 4. 配置轴确认话术

将 [SKILL.md](../SKILL.md) 中的七个轴作为互不绑定的选项一次性确认（用户已明确的直接采用）：

```text
开始前确认七个互不绑定的选项：
1. 产出类型：单图 / 图片系列 / 短视频 / 分镜板 / 仅分析；
2. 主题域：时尚编辑（默认）/ 产品展示 / 品牌广告 / 食物餐饮 / 人物肖像 / 抽象概念；
3. 风格与基调：写实 / 编辑感 / 电影感 / 极简 / 其他；
4. 画幅与比例：社媒竖版 9:16 / 电商方图 1:1 / 海报横版 3:2 / 自定义；
5. 生成方式：直接生成 / 先出分镜或关键帧预览确认后生成 / 仅交付制作包；
6. 生成能力：使用当前 Agent 原生能力 / 指定工具；无可用能力时退化为提示词+制作包；
7. 数量与节奏：单张 / 系列张数 / 视频时长与镜头密度。
```

每项先给一句推荐理由，不连续追问。用户要求 Agent 决定时选推荐项并标注为"可逆假设"。

## 5. 工作模式

### 分析（仅诊断）
用于用户只给素材要求拆解。交付视觉诊断与可复用视觉配方，不生成额外资产，除非被要求。

### 一键出品
用于用户给素材或创意并要求直接做。按 SKILL.md 流程端到端执行：诊断 → 创意 → 计划 → 编译 →（可用时）生成 → 质检 → 修正 → 交付包。不逐步请求批准，但关键未知仍最多问一个问题。

### 定向修正
用于用户返回已有结果要求改进。先指出最多 7 个最影响结果的问题，再给完整重写版；优先处理目标冲突、动作密度、素材职责错配、主体变形、时间超载与品牌交付风险，不靠追加形容词修复。

### 成片复盘
用于用户返回生成图/视频。先用全片等间隔抽帧建立镜头地图，再对失败动作高频抽帧并测量实际切点/转场边界；区分成功层与失败层，输出 `保留项`、`唯一主修层`、`重试指令`。只修证据指向的层，不推翻已成功部分。

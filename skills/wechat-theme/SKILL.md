## 用途与触发

本号（咪咪AILab）任何一篇文章进入排版环节时用：写 DOCX 构建脚本、生成 DOCX、导入公众号编辑器后复验版式与字数。触发点：deep-article-production Stage 3 版式落实、Stage 5 的 DOCX 构建与导入复验。不是深度文章也一样用——只要是这个号发出去的文章，主题就这一套，不逐篇另定。

## 核心原则

- 版式学参考文，配色用自家系。参考文（开源星探 Stitch 篇）的骨架照学：编号四段式节标题、底纹小标题、虚线引用框、表头实底表格；它的翠绿一概不用。
- 同类风格即可，不求逐项全同。网页端做不到的元素按规格的近似方案落地，不为凑形似把正文改坏。
- 固定下来：自 2026-11-23 起每篇按本主题排；改版须经 V哥点头、升版本号并同步规格文件，不在单篇里私自变样。

## 色板（自家系，与封面同家族：墨绿 + 暖金）

| 用途 | 色值 |
|---|---|
| 主强调 墨绿 | #14532D（编号、表格表头实底、代码块左竖条、H2 标题深绿、关键词与结论句标色） |
| 标题 / 正文深灰 | #1F2937 档 |
| H3 底纹 暖金浅色带 | #F5D98B（网页端半透明感）；DOCX 近似 #FBF0D3 实色浅金 |
| 代码块底 | #F2F0EB |
| 引用虚线框边 | #9CA3AF（1px 虚线，框底比页面略亮） |
| 分隔细线 | 浅灰 1px |

## 逐项规格摘要（全文见规格文件）

- **H1**：20pt 粗体深灰，下方可带一条墨绿细线。
- **H2 四段式**：大号编号 `01 / 02 / 03 …`（粗体墨绿）＋编号下方小号大写英文标签（字母间距拉开，灰，如 PART / LAST）＋中间 1px 细竖线＋右侧粗体节标题。结尾节编号位用 `///` 代替数字。DOCX 里编号与标题同行排布（见实现要点），英文小标签不强加。
- **H3**：粗体，整行带一条暖金底纹色带，紧贴文字、略宽于字高。
- **正文节奏**：无衬线，行距 1.7–1.8，段距约一个字高以上，不缩进；开篇直入正文，文首不加导读框。
- **强调规则**：关键词 = 墨绿粗体无底色；结论句 = 整句墨绿粗体；普通强调只加粗不上色。
- **引用 / 示例框**：1px 虚线边框（#9CA3AF）+ 略亮底 + 内边距 16–20px，无左竖条（网页端圆角，DOCX 直角近似）。
- **代码块**：浅底 #F2F0EB + 左侧 3–4px 墨绿竖条 + 等宽字体，无行号。
- **表格**：表头行墨绿实底 + 白字粗体；首列墨绿等宽粗体；细网格线，行高疏。
- **分隔**：节与节之间 1px 浅灰细线。
- **有序列表**：网页端是墨绿实心圆 + 白数字徽章；DOCX 做不到，用墨绿粗体「1.」近似。
- **文末**：固定 AI 声明与一手来源清单，不另加组件。

## DOCX 实现要点（python-docx）

- H2 用 run 拼：编号 run（18pt 粗体墨绿 #14532D）+ 空格 + 「│」灰色竖线 run + 空格 + 标题 run（16pt 粗体墨绿）。标题文字本身一字不动，编号与竖线是排版元素、不算正文。
- H3 底纹、引用框底、代码块底：段落底纹（w:shd fill），H3 用 #FBF0D3，代码块用 #F2F0EB。
- 表格表头：逐 cell 设 shading #14532D，文字白色粗体；首列文字墨绿粗体。
- 代码块左竖条：段落左边框 pBdr，墨绿、粗细取 3pt 档（sz=24）。
- 引用框：四边 pBdr dashed（#9CA3AF）+ 浅底段落底纹。
- 分隔细线：段落下边框 pBdr 浅灰 1px。
- 构建后自检必做：全文可见字符与源稿逐字比对（剥除编号/竖线等排版元素后必须相等）、H1/H2 计数、表格数、主题元素抽查（表头 fill、代码块左边框、虚线框段落数）。

## 导入实测教训（2026-11-23，Matt Pocock 篇，必读）

- **引用块虚线框会被编辑器压平**：DOCX 的 dashed 四边框导入后没了，引用块变成深底实色块 + 左侧绿竖条。其余主题元素全部存活：H2 编号 + 竖线 + 绿字标题在、节标题明显大于正文、表头墨绿底白字在、首列绿字在、代码块左绿竖条在。复验时逐项报「在 / 没了」，没了的先报告、不自行修补；虚线框丢失是已知边界，不是构建错误。
- **编辑器字数不计表格、也不计大段引用 / 代码块**。字数对账必须按「散文正文」口径：本篇文件口径非表格正文约 4,499 字，编辑器实数只有 3,082——按总字数比例折算会高估近 800 字，直接跌出 3,500–4,500 区间。估算公式：编辑器字数 ≈ 散文段落字数（表格、代码块、引用块整段剔除后再数），宁可按剔除后口径卡下限留余量。
- **增补只能补散文**：字数不够时，从母稿补回被压缩掉的散文段落（已核内容、不加新事实），补进表格/引用块等于没补；增补后必须重开一轮全文 Checker，通过后把增补段落改进现有草稿（直接在草稿里改，不删了重建），再复验编辑器实数落在区间内才算完。

## 验收

- DOCX 自检四项全过：字符逐字一致、H1/H2 计数对、表格数对、主题元素抽查在位。
- 导入后复验六项有记录：正文完整、编辑器字数实数（散文口径，落在目标区间）、标题一致、封面已设、作者咪咪、主题元素逐项在 / 没了。
- 字数只认编辑器实数对账，估算与实数不符时以实数为准并按上面教训处置，不放宽门槛。

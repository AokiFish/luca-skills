# login-discipline

Luca 没空反复登录、输验证码。登录步骤是稀缺资源，按一次门控花，不按步骤滴漏。

## 规则

1. 最小化身份步骤：一次任务只用一个连续浏览器会话；优先走已持久会话的路线（例如云浏览器里已登录的 GitHub）；不可避免的登录只打包成一次门控，绝不每步都问。
2. 登录服务时直接用已登录的 Google 账号点选登录，不保存密码、不填安全卡。
3. 不许保存 Luca 的 Google 密码。已存的 Google 密码要删，只能 Luca 自己在 app 设置里删，agent 删不了；以后 Google/Kaggle 登录一律走他已登录的浏览器会话，不走保存的密码。
4. 绝不向 Luca 要验证码；碰到 2FA 的检查就停，等他本来就要登录时再说。X 的码由 Luca 从身份验证器 App 提供，不指他去 g.co/sc 取码。
5. 登录失败要留足冷却：2 小时不够，短时间连续重试只会再失败；下次重试前定更长冷却间隔。
6. 登录等待中的浏览器窗口死了要立即重开并告诉 Luca，不要让线路停滞。
7. X 登录走次要的「登录 / Sign in」链接（mode=login）；首页大号「继续使用 Google」按钮与邮箱输入框是注册通道，走大按钮等于主动进注册流程。
8. Cloady 控制台只走 GitHub 登录，Gmail 邮箱验证码路线不再由咪咪管理。
9. 云浏览器没登录就是没登录，不许反复试登录；Luca 叫停就停。

## 验收

- 汇报里出现登录/验证码请求时，必须说明这是单次打包门控、为什么绕不过去。
- 出现保存密码、索要验证码、反复重试登录，三者有其一即违规。

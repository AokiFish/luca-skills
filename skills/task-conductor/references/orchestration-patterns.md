# 编排模式

## 模式 A：串行流水线（最常见）

```
素材/剧本 → 制作成片 → 多平台文案 → 逐平台发布 → 逐平台核验
```

特点：每步依赖上一步产物；不能并行，但可在“文案”阶段之后扇出。

示例节点：

| # | 节点 | Skill | 依赖 |
|---|---|---|---|
| 1 | 生成视频 | `doubao-creative-video` | - |
| 2 | 生成多平台文案与字幕 | `video-publish-pack` | 1 |
| 3 | 发布抖音 | `sau-publish` | 2 |

## 模式 B：一物料多平台扇出

```
content-pack.json ─┬─ 抖音（sau-publish）
                   ├─ 小红书（sau-publish）
                   ├─ B 站（sau-publish，需 tid）
                   └─ YouTube（sau-publish，需 visibility）
```

要点：
- 内容包只生成一次，各平台共享同一份 `videoFile`。
- 各平台发布彼此独立，可并行；但同一账号的登录态不要并发使用。
- 每个平台都要单独核验，不因一个平台成功就推断其它成功。

## 模式 C：条件分支

| 条件 | 分支 |
|---|---|
| 用户没给成片，只给创意 | 先走制作 Skill，再走文案与发布 |
| 已有 `content-pack.json` | 跳过文案，直接 `sau-publish` |
| 账号 cookie `valid` | 跳过登录 |
| 平台无 CLI（TikTok） | 标注需人工/浏览器版，不硬编命令 |
| 视频画面已有内嵌字幕 | 不再生成外挂字幕 |

## 模式 E：GitHub 开源项目教程视频（本工作流固化）

```
GitHub 仓库 + 官网 + 设计版卡片源 + 操作录屏 + 参考音色
        │
        ├─ 节点1：写解说脚本（含画质设置、快捷键等实操要点）
        ├─ 节点2：audio_to_audio_plus 克隆参考音色 → 旁白 WAV（要求全程语速一致）
        ├─ 节点3：video-use 分段提取设计卡片 + 内嵌操作录屏（pad 到 1080p、静音）→ concat → mux 旁白
        │         注意：视频总时长必须 ≥ 旁白时长，片尾用亮帧静帧补满，不能用 -shortest 截断结尾
        ├─ 节点4：video-publish-pack 多平台文案（GitHub 必带标签）
        └─ 节点5：sau-publish 逐平台发布
```

**关键经验（踩过的坑）**：
- 旁白时长 ≠ 视频时长。成片必须 ≥ 旁白，否则 `-shortest` 会切掉结尾"点赞下期见"。
- 补时长用**亮帧静帧**（从片尾 CTA 完整显示那一帧），不要用原片尾动画最后一帧（那帧在渐暗，拼上去会闪）。
- concat list 文件必须 UTF-8 无 BOM。
- 音色克隆要在 prompt 里显式要求"全程语速一致，不要开头慢后面快"，否则 TTS 起头偏慢。
- 操作录屏如果分辨率不是 1080p（如 1920×988），pad 到 1920×1080 黑边补齐。
- 输出目录：`out\tutorial\<项目名>-<日期>\`。

**典型节点表**：

| # | 节点 | Skill/工具 | 依赖 | 输入 | 输出 | 验收 |
|---|---|---|---|---|---|---|
| 1 | 写解说脚本 | （主 Agent 写） | - | 仓库 README + 官网 + 录屏内容 | 脚本文本 | 覆盖安装→核心操作→快捷键→进阶插件→片尾 CTA |
| 2 | 克隆音色旁白 | `audio_to_audio_plus` | 1 | 参考音频 URL + 脚本 | voiceover.wav | ffprobe 时长 ≥ 脚本预期 |
| 3 | 剪辑成片 | `video-use`（ffmpeg） | 2 | 设计卡片源 + 操作录屏 + 旁白 | final.mp4 | 抽帧验证：操作录屏段、片尾 CTA 完整、无拼接闪烁 |
| 4 | 多平台文案 | `video-publish-pack` | 3 | final.mp4 + 内容摘要 | content-pack.json | GitHub 标签在每个平台标签列表中 |
| 5 | 逐平台发布 | `sau-publish` | 4 | content-pack.json | 各平台作品 | 后台状态=已发布 |

## 模式 D：失败与回退

| 失败类型 | 判定 | 回退动作 |
|---|---|---|
| 环境缺失（venv/浏览器/conf.py） | CLI 启动即崩 | 读 `sau-publish/references/windows-setup.md` 补齐 |
| 登录失效 | `check` 返回 invalid | 走登录流程，让用户扫码 |
| 文案超限 | 校验脚本 error | 退回 `video-publish-pack` 重写 |
| 发布状态不明 | 日志冲突/验证码未过 | 先核验后台，再决定是否重试 |
| 连续 2 次失败 | 同一节点 | 停止并报告卡点 |

## 编排计划模板

```markdown
## 目标
<一句话>    交付物：<文件/链接/平台状态清单>

| # | 节点 | Skill | 依赖 | 输入 | 输出 | 验收 |
|---|---|---|---|---|---|---|
| 1 | | | - | | | |
| 2 | | | 1 | | | |

并行组：
前置与风险：
验收汇总（执行后填写）：
- 节点 1：<产物路径> / <校验结果>
- 节点 2：<平台状态> / <核验证据>
```

## 验收清单原则

1. 每条验收都必须是**可检查的事实**，不能写“质量好”“效果不错”。
2. 产物类：文件存在、可打开、校验脚本通过、内容与需求一致。
3. 发布类：平台后台状态、标题、时长、发布时间四项齐全。
4. 交付类：已通过 `present_files` 或 `RichMediaCard` 真正交付给用户。
